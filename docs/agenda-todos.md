# Agenda 与 TODOs

[返回首页](../README.md) · [查看 Org 分类总表](org-and-aster.md)

Agenda 和 TODOs 读取同一批 Org 文件，但回答不同问题：

- **Agenda**：什么时候发生？显示 Event、有具体钟点的未完成 Task，以及今天可执行的 Habit（无论是否带具体钟点）。
- **TODOs**：还有什么未完成？显示无日期或只有日期、没有具体钟点的非 Habit Workflow 条目。

![Agenda 示例](../assets/screenshots/agenda.png)

## Agenda 显示什么

| 条目 | 是否进入 Agenda | 显示方式 |
| --- | --- | --- |
| 无 Workflow 的全天 Event | 是 | 紧凑全天条 |
| 无 Workflow 的时间范围 Event | 是 | 时间范围在上、标题在下 |
| 有 Workflow 的日期型 Task | 否 | 留在 TODOs |
| 有 Workflow 的定时 Task | 是 | 精确时刻在上、Workflow 条目在下 |
| Habit 到达可执行窗口 | 是 | Workflow + Habit 节奏和历史 |
| 普通 Note/Container | 否 | 留在 Files/Search |

## TODOs 显示什么

![TODOs 示例](../assets/screenshots/todos.png)

TODOs 保留所有未完成且没有具体钟点的非 Habit Workflow 条目，包括：

- 完全无日期的 Task。
- 只有日期的 `SCHEDULED` Task。
- 只有日期的 `DEADLINE` Task。
- 配置为 Project 的 Workflow 条目。

Habit 是例外：默认到达可执行窗口后，才在今天的 Agenda 时间线出现。没有具体钟点时也不会被移入或重复显示在 TODOs。

列表按真实文件和 Org 层级组织。可见父 Task 下的可见子 Task 会保持嵌套；纯结构 Container 不会被错误显示为 Task。

### 查看尚未到期的习惯（iOS/iPadOS build 14）

在设置 → 日历与 Agenda 中，可以开启「今天显示所有习惯」，默认关闭。开启后，今天也会显示尚未到计划日期的习惯，并标注「未到期 · 下次日期」；有钟点时一并显示。

这只是显示选项，不会提前通知、增加角标或日历标记，也不会修改 Org 日期和重复规则。当天完成的习惯仍保留一条，不能重复打卡。

如果只想集中回顾习惯，可以创建普通 Perspective，仅勾选 Habit 类型。它包含尚未到期的习惯，不依赖上述开关；仍遵守 Agenda 来源、归档排除和你设置的筛选条件。无需新增习惯模块。

iOS/iPadOS build 14也修复了 iPad 输入 Perspective 名称时编辑窗口意外关闭的问题。键盘弹出或收起不会再切换页面布局，输入中的草稿会保留。

## Overdue 的规则

iOS/iPadOS build 14中，更换设备时区或在新时区重新打开 Aster，会重新解析日期并刷新 Agenda、Journal、提醒和角标。普通 Org 的 `09:00` 仍是当地上午九点，不会因为复用旧缓存而变成前一天。未保存的编辑文字会保留；Widget 在新的快照准备好之前不使用旧时区数据。

系统提醒若明确指定了时区，则保持原来的真实时刻。详见[时区原文示例](org-and-aster.md#16-时区与跨地区提醒iosipados-build-14)。

- 只有未完成的 Workflow 条目才会成为 Overdue。
- 日期型 Task 过期后留在 TODOs，并显示“逾期 1 天”或“逾期 N 天”的紧凑状态，不会被搬到今天。
- 定时 Task 在当天时刻已过时会显示“已逾期”，之后按日历日显示过期天数；Agenda 中的时间也会变红。
- `SCHEDULED` 与 `DEADLINE` 使用同一套过期天数。条目由 Aster 创建还是从 Apple Reminders 同步而来，不会改变显示规则。
- 今天顶部可以显示历史 Overdue 数量；点击会以滚动动画前往最近的 Overdue 原日期。
- 多条 Overdue 仍保留在各自日期，用户可继续向上查看，不合并成一条伪造任务。
- 没有 Workflow 关键字的 Event 不使用 Task 的 Overdue 语义。

## 新建时的 Event/Task 选择

Agenda 的 `+` 打开快速新建。上方两段选择只决定 Org 类型，不会因为输入日期或时间而自动改变：

| 选择 | Org 语义 | 时间精度 |
| --- | --- | --- |
| 日历图标 | Event，无 Workflow 关键字 | 全天或开始—结束区间 |
| 勾选图标 | Task，使用选定 Workflow 关键字 | 无日期；各日期可选具体时刻 |

### Event

- 不输入时间：写入全天活动时间戳。
- Event 可以分别选择开始日期和结束日期；同一天仍写一个活动时间戳，跨天则写标准 Org 日期区间：

  ```org
  * 出差
  <2026-08-28 Fri>--<2026-08-30 Sun>
  ```

- 只输入 `9:00`：默认写成 `09:00-10:00`。
- 输入 `9:00-10:15`：保留指定区间。
- 跨天并带时刻时，同样写一个标准活动时间戳区间，例如
  `<2026-08-28 Fri 09:00>--<2026-08-30 Sun 18:00>`。
- 已经过的隐式时间会推到下一天；明确输入的日期保持用户选择。

### Task

- 计划日期和截止日期均未设置：写入无日期 Task，进入 TODOs。
- 可以单独设置 `SCHEDULED`、`DEADLINE`，也可以同时设置。没有具体时刻时，仍留在 TODOs。
- 为当前字段打开 At a time：写入该字段的具体时刻，进入 Agenda，并按该时刻提醒。
- Task 不写结束时刻；它不是 Event 区间。

日期型 Task 可以在新建页中预览整天，但不会因此进入 Agenda。没有设置日期时不显示时间轴；移除日期后的预览规则见[分别编辑计划和截止日期](#分别编辑计划和截止日期下一版本)。

### 星期规则的提醒（iOS/iPadOS，未发布）

未完成的 Task 如果使用 Aster 支持的工作日、周末或自定义星期规则，并在标题中带有具体时刻，也会在符合规则的当天提醒。仅有日期、已经完成或没有 TODO 状态的 Event，不会因此自动提醒。任意 Lisp 表达式不会执行。

例如下面的条目会在周六和周日的本地 10:00 提醒，时区或夏令时变化后仍遵循本地时钟：

```org
* TODO Weekend review 10:00
SCHEDULED: <%%(memq (calendar-day-of-week date) '(0 6))>
```

这类条目的角标到当天午夜结束，同一条任务在一天内只计一个角标。通知中的 Complete 不会把已经完成的任务重新打开。

稍后提醒始终保留原来那次提醒的归属，跨午夜或再次延后也一样。例如周日 09:55 将周六的通知延后到 10:05，周日原定 10:00 的提醒仍会保留。缺少有效原始时间的旧通知会提示已过时，不会修改条目；请在 Aster 中打开对应条目。

## 新建页可直接设置什么

新建页与详情页的通用字段保持相同顺序。标题固定在滚动区域上方，其余设置依次为：

- Item Type，以及 Task 的 Workflow 状态和适用的进度设置
- Priority
- Tags
- Task 的计划日期和截止日期：可分别设置日期、具体时刻和重复规则
- Event 的开始/结束日期和可选区间时刻
- Event 和 Task 的标准 Org Repeat 或 Weekday Diary；Task 各日期保留自己的规则
- 待添加附件
- 一条写入 LOGBOOK 的 Note
- 被动显示的 Event & Task Inbox 目标

标题固定在上方，各项设置入口位于下方同一个滚动区域，不再藏在 Show More/Show Less 中。Task 的 Scheduled 和 Deadline 在原页面分别设置，不进入日期子页面。

长标题会按手机可用宽度自然换行，完整内容需要多少行就显示多少行，不设行数上限，也不会把展示换行写入 Org 标题。时间轴预览中的标题只显示一行，超出条带宽度时以省略号结尾，不会撑宽页面。

时间轴会按字体和时间文字的实际宽度减少刻度标签，避免英文 AM/PM 或较大字号挤在一起。两端标签保持完整，事件区间与任务时刻的位置不变。

夏令时切换当天，自动定位沿用实际刻度，包括半小时切换的时区。不是本地整点的刻度会显示分钟，最后不足一小时的区间也保留实际宽度。

新建时间轴位于日期区域，并突出显示当前草稿。新建 Event 时只显示当天已有的 Event，新建 Task 时只显示定时 Task；切换类型或日期后，内容会立即更新。Event 按实际区间绘制，Task 只标出时刻，左右滑动可以查看当天其他时段。

新建 Event 时，跨午夜 Event 会显示与当天相交的部分，全天 Event 单独紧凑排列。新建 Task 时不显示这些 Event；无时刻的 TODO 仍不占时间轴。

时间显示跟随系统的 12/24 小时制，不需要在 Aster 中再设置一次。Org 时间戳仍按 `HH:mm` 保存，标题和模板中的原文不变。在系统切换时间制后返回 Aster，待发送通知的时间文案也会更新；提醒时刻不变。

WebDAV URL、文件与目录名、Journal 文件名规则、Capture 路径与提示回答、Agenda 标签和 Perspective 过滤器等长值编辑也遵循同一换行规则。时间轴只保留帮助辨识时间范围的淡色平面底。点击 Add 后，标题、规划、属性、Note、链接和附件复制仍作为一次事务写入。

## 日历与时间线

- 第一次打开时默认月视图；之后会记住最后选择的 Week、Month 或 Year，即使结束并重新打开 Aster 也会恢复。下方 Grabber 每次只切换一个相邻级别。
- Agenda 和 Journal 的 Month 都使用本地化的三字母等效星期标题（例如 `Mon`、`Tue`、`Wed`），手机紧凑布局与 iPad 宽布局保持一致，不再使用容易混淆的单字母标题。
- Agenda 和 Journal 的 Week 复用同一个五列事件日期轨道，不是普通七日页。Agenda 提供当前选中日、含有非 Habit Agenda 条目的日期和外部全天日历日期；Journal 提供当前选中日、已有日记的日期和同一外部日历覆盖。任一方向没有内容日期时都会补一个相邻空日期，因此可以继续向过去或未来翻，不会停在最早或最晚记录。跨度很长的来源只提取当前浏览位置附近所需的日期，不会把整段日期全部展开；重叠横条只有在整段都空闲时才占用一行，达到固定显示上限后会省略多余横条而不会互相压住。被省略的日期在交界处显示一条对齐的撕口，周末沿用日历灰底，每列分界一直延伸到轨道底部。单日和跨日条目只显示来源色横条，不在横条内塞文字；Agenda 中有 Workflow 关键字的日期在居中的星期文字旁叠加一个不占布局的标志。每次有效横向松手都固定前进或后退五个日历日，不会因拖动距离改变步长，并使用和 Month、Year 相同的整页方向切换动态；只有拖动时，最左列里的内容才会在一层清晰、无模糊的透明折射区下随拖动渐进放大，最高约 6%，并产生轻微位移。放大始终限制在该列的固定玻璃遮罩内，折射区只露出固定的右侧光学边界，背景、周末灰底和日期边界保持不动。静止时不存在可见玻璃层、色差、模糊、渐变、边线或重影。
- Week 松手后只完成一次五日整页方向切换，不会再叠加第二次吸附或弹簧回弹。iPad 横屏左栏使用和 iPhone 相同的五列轨道，右栏仍保留同步月历；Android 横向平板在 Navigation Rail 右侧同样把日历和时间线留在左侧内容栏。
- 日历固定，下面时间线独立滚动，并可向过去和未来继续扩展。
- 首屏仍把今天顶格显示，但过去日期已经位于其上方；第一次拖动就是原生滚动，不需要先拖一次来“解锁”时间线。
- 时间线顶部日期变化时，日历选中日同步跟随。
- iPhone 与 Android 手机上方日期、日历和时间线分别共用左右各 18pt/18dp 的固定内容边距；自定义字体或很长的全天条目只会在自己的圆角条内省略，不会把整页向右撑偏。即使先进入 Files、Journal、Search 或 Settings 再返回 Agenda，后台保留的页面也不会再把 Agenda 与根导航撑偏。
- Week、Month 和 Year 使用相同的整页方向动画；iOS Reduce Motion 或 Android 的系统动画辅助设置会减少空间运动，但不改变结果。
- iPad 横屏把完整时间线和五列 Week 轨道放左侧、同步月历放右侧。Android 横向平板使用左侧 Navigation Rail，其右侧的 Agenda 左栏放日期、日历和时间线，右栏放同步月历或所选详情。TODOs 和 Perspective 不保留无意义的大日历。

## 条目操作

- 轻点 Task 的左侧 Workflow 图标或当前关键字胶囊：直接打开同一份完整状态列表。两者都不猜测完成、重开或 Habit 打卡动作，而是让用户明确选择关键字。
- 轻点标题或其他区域：打开同一个详情页。关键字的点击范围紧贴可见胶囊，不向标题区域扩张。iPhone 使用底部面板，iPad 使用锚定 popover，Android 使用可滚动的原生状态面板；选中后立即写入并关闭，不需要再点 Done。当前状态以关键字自己的颜色和填充表示，不额外绘制勾选。非重复条目切到 Terminal 后会在原位置短暂停留以确认新状态，然后才从活动列表消失。
- 长按 Task：只打开 Schedule、Move/Archive、Note 和 Delete 等紧凑条目操作，不再重复显示关键字列表；Android 使用锚定在条目附近的原生弹出菜单。
- 长按 Event：打开可用的日程、移动/归档、Note 和删除操作。
- Agenda 和 TODOs 不使用左右滑动改变 Workflow，避免与滚动和系统手势冲突。
- 详情页关闭时把当前有效草稿一次写回源文件；没有额外 Save 按钮。

详情页的主要顺序是：Item/History → Schedule/Repeat/Reminder → Content → Attachments → Notes → Subtasks → Delete。Delete 为红色，并在底部导航之上保留足够滚动空间。

下一版本的 iPhone/iPad 详情页会将顶部可编辑标题稍微放大并使用半粗字重，与下方设置项区分。短标题和长标题使用同样的层级，仍跟随所选字体和系统文字大小；字段顺序与保存方式不变。

标题会按实际宽度自然换行，不再根据字符数量决定是否显示多行。浅色、深色和较大字号遵循同一规则，视觉换行不会改变 Org 标题原文。

同一版本还会去掉详情中 Add Attachment 和 Delete 的图标。Add Attachment 文字左对齐；Delete 文字居中、加粗并保持红色，删除前仍需确认。

iPad 横屏时，Agenda 详情在右侧显示源码按钮，不需要旋转屏幕。返回会先保存，再恢复右侧月历；保存失败时保留当前输入和详情页。

### 分别编辑计划和截止日期（下一版本）

新建与编辑 Task 都在原页面显示 Scheduled 和 Deadline 两个独立区块。两项开关可以同时打开，各自显示日期、时刻和重复规则，不需要切换编辑模式。

每项开关只启用或移除自己的日期，不影响另一项。两块使用同样的日期、时间和重复控件，但分别保留值。打开「At a time」后，时刻显示在对应 Date 行的日期后面；下方只保留时刻开关，不再重复显示时间。

新建时打开「At a time」，默认取下一个整点，例如现在 14:35，默认为所选日期的 15:00。Scheduled 和 Deadline 各自应用这一规则，与新建 Event 一致。若选择今天且下一个整点跨过午夜，则使用明天 00:00；编辑已有时刻不会重新取整。

Scheduled 表示计划开始处理的日期，Deadline 表示完成期限。它们不是两种任务类型，也不要求有具体时刻；没有时刻的 Task 仍留在 TODOs。

日期直接使用系统选择器，不再进入 Scheduled 或 Deadline 子页面。新任务最后点 Add，已有任务返回时保存。

在新建页面切换 Event/Task 时，会分别保留未提交的任务日期草稿和事件时长。

重复规则从原页面打开共用的规则面板。点 Done 或关闭面板回到原表单，不会直接保存任务。

选择每周重复时，在同一次选择中尝试其他星期再选回原来的星期，日期不会多跳一周。关闭重复面板时才按最终选择确定日期，不会把每次点击当作推进下一期。

工作日、周末或自定义星期组合使用标题中的共享时刻。如果两个字段都用这类规则，请使用相同的时刻和全天设置；冲突时会提示并保留输入，不会写入。若需要不同时刻，可以使用普通重复器或拆成不同任务。

移除某个日期不会影响另一个。只查看日期或修改标题、标签，也不会改写未修改的时间戳。计划日期晚于截止日期时会显示提示，但不强制调整。

新建 Task 时，上方的日期摘要和时间轴跟随最近修改且有效的日期。移除该日期后，预览会使用剩余日期，并保留其全天或具体时刻。只查看另一项不会改变预览；两项日期都移除后，预览才会隐藏。

同时新增两个日期时，Aster 将它们写在标题后的同一条标准 Org planning line 中。完成任务新增的 `CLOSED` 也共用这一行，确保 Emacs 能一起识别。

已有源文件如果包含多个同名日期字段，修改该日期会提示先检查 Org 源文件。Aster 不会自行猜测哪一个值应该删除。包含两个日期的用法见 [Org 示例](org-and-aster.md#同时有计划和截止日期)。

## 自定义视图入口

打开 Views 左侧的三横线二级菜单可以选择；屏幕上从上到下依次是：

- Agenda
- TODOs
- Journal
- 已保存 Perspective

Views 始终是一级入口，二级菜单只切换它内部的内容。Aster 不提供固定 Projects 页面；不同用户可按 Workflow、Tags、来源、日期状态等组合 Perspective。**设置 → Tasks & Workflow → Views** 里的 Projects 与 Anniversaries 是可选模板，开启后也只会创建普通、可编辑的 Perspective。
